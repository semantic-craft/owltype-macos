# Build, delivery, and acceptance tools

## Overview

This directory owns executable tooling around the Swift/Rust product: pinned resources, reproducible build inputs, release cohorts, distribution, installation maintenance, and evidence collection. The tools have different authority and side effects; a successful static check is not installed-app or real-host acceptance. Test-only files sit beside the production entry points but are not architectural interfaces.

## Invariants

- `[msime_pin.py:main]` keeps the source/manifest identity centralized. `[fetch-msime-resources.py:verify]` checks both size and digest before selecting product files. `[fetch-msime-others.py:verify_database]` checks the retained four-table contract, exact row counts and row hashes. `[fetch-rerank-models.py:load_lock]` validates role, size, digest, license/notice, and path constraints before download/publication.
- `[build-owltype-msime-seed-db.py:check_seed_dbs]` checks the pinyin suffix tables, Wubi provenance/counts/required and forbidden pairs, and English schema. `[resource_publish.py:publish_artifacts]` restores backups on failure; this is rollback-capable sequential replacement, not a simultaneous atomic view of all files.
- `[build-sparkle.py:main]` binds reuse to upstream revision, patch/builder identity and framework receipt/UUID evidence; it builds in temporary source rather than mutating the source submodule. `[build-rust-ffi.sh:--native-only]` is the explicit development architecture exception; release outputs cover both supported architectures.
- `[release-cohort-state.py:load_validated]` rechecks source, seed, output root, app, and recorded artifacts before operations. `seal` advances built → signed → notarized → stapled with bounded retry policy; rejected/failed transitions remain failed. Dependency order requires app eligibility before packages and package eligibility before DMG.
- `[release-cohort-state.py:verify_chain]` binds artifacts, exact corresponding source, inventory, and appcast signature. `authorize_publish` requires the release orchestrator's final-stage environment marker and binds the selected ten assets; authorization is local state, not a remote upload.
- `[release_source.py:git_source_snapshot]` requires pinned submodule snapshots and rejects unsupported tree entries. `write_deterministic_archive` normalizes entry order, modes, owner/time metadata and gzip metadata. `[inventory-release-bundle.py:main]` writes final inventory outside the app after signing/stapling; `[finalize-release-bundle.py:main]` performs mutations before signing.
- `[owl_distribution.py:build_publish_plan]` orders ten immutable versioned assets before the mutable latest pointer/feed. `publish` checks store readbacks before one `store.commit()` and then performs public HTTP verification. `GitHubDownloadsStore.put` uploads binary release assets immediately while staging site files locally; `GitHubDownloadsStore.commit` pushes the site changes together. Existing immutable content with different bytes is rejected.
- `[check-staged-pkg.py:main]` requires the inert staged app archive and rejects unsafe archive layout, paths, links, and corrupt contents. `[safe-extract-tar.py:main]` rejects traversal, duplicate entries, links, and special types before extracting into a fresh destination.
- `[secret-finding-policy.py:main]` normalizes scanner findings and applies exact bounded policy exceptions; report output redacts finding contents. `[check-rust-delivery.py:validate_app]` rejects legacy runtime delivery and checks exported FFI symbols, resources, helper executability and architecture.
- `[verify.py:snapshot]` includes tracked/untracked work and submodule identity before/after execution; receipts distinguish stage failure, interruption, source changes, and incomplete/skipped tests. `[merge-pr.py:passing_receipt]` requires a full clean passing receipt for the exact head, then the merge command fences the head SHA.
- `[check-live-ime-version.py:assess]` and `[check-installed-process.py:main]` distinguish a current installed executable mapping from an old process/bundle path. `[check-ime-host-evidence.py:validate]` requires a bound host, timing and changed saved document; screenshots and human observation remain separate acceptance evidence. `[pinyin-parity.py:main]` establishes compared traces, not native-host typing.
- `[preinstall:installer_state_dir]` preserves staging outside the live app and records session context. `[postinstall:installer_state_dir]` commits the verified app via its privileged command, then runs the installed finishing command in the GUI user's session. `[cleanup_app_registrations.py:prepare]` rejects protected, symlinked, or running executable roots and only unregisters within the supplied cleanup root.

## Side Effects

- Resource/build entry points download pinned inputs, create caches and generated seed/model/database/framework/library/header artifacts, and invoke Rust/Xcode tools. `[owl-seed.sh:lockf]` serializes seed generation. `[fetch-rerank-models.py:materialize]` verifies staged inputs before individual file replacements.
- Release preparation changes selected build outputs and cohort JSON/receipts; signing/notarization can use Keychain and Apple's network services. `[check-release.sh:notarytool]` also queries notarization history, so it is not an entirely offline check. `[owl_distribution.py:GitHubDownloadsStore]` uploads GitHub release assets and commits/pushes the configured website repository.
- `[verify.py:run_step]` executes the chosen verification plan and writes evidence outside the checkout, terminating the subprocess group on interruption. `[live-test.sh:TEST_RUNNER_]` can load live provider credentials. `[merge-pr.py:main]` can squash-merge and delete the PR branch after receipt validation; dry-run avoids the merge.
- Installation and maintenance tools can sign/copy/remove installed apps, stop user processes, alter TIS selection/enabling, clear scoped caches, update LaunchServices, and remove Owltype user data/receipts. `[clean-dev.sh:--apply]` is the explicit deletion mode; its default reports candidates. `[cleanup_app_registrations.py:--remove]` removes the prepared caller-owned tree.
- Host and smoke tools can focus/create documents, inject input, alter trace defaults, and write logs/evidence. `[input-claims.sh:exec]` forwards claim operations that can update the external claim store. Diagnostic readback does not itself establish successful input in every host.

## Verification

From the repository root, `python3 scripts/verify.py navigation` checks documentation navigation through the normal receipt wrapper. `make release-cohort-selftest` runs isolated release-state/composition regression fixtures; the broader quick/full gate is implemented by `gate.sh` and can build/download resources. Use the relevant focused selftest beside a changed tool, and reserve live/install/release commands for their operational acceptance scope. This documentation pass read production implementations, excluded test-only files and ignored caches, and did not run builds, downloads, signing, installation, publication, merges, or live input.
