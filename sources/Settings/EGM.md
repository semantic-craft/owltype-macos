# Settings

## Overview

Native settings and onboarding surfaces, preference adapters, and template-library editing. Swift owns window/UI state, native dialogs, and explicit platform effects; keyboard catalogs, storage transactions, template parsing, and validation delegate to the Rust application core. The current shortcut page routes through the unified template library; legacy prompt and quick-send stores remain for compatibility and migration. [OwlSettingsWindow.swift:OwlSettingsWindow] [OwlSettingsView.swift:OwlSettingsView] [OwlTemplateMigrationView.swift:OwlTemplateSettingsRoute]

## Invariants

- Keyboard switch catalog order/identity must match Rust metadata. Preference writes and successful runtime activation are separate outcomes; application refuses pending template recovery. The current application path returns no written YAML files; legacy export/preview remains an explicit API. [OwlKeyboardSettingsCatalog.swift:OwlKeyboardSettingsCatalog] [OwlKeyboardSettingsApplication.swift:apply] [OwlWritePreviewSheet.swift:applyRealMachine]
- Candidate appearance edits pass through one lifecycle. Automatic orientation follows engine style; scroll rows clamp to 1–4. Missing named fonts retain the requested selection and expose fallback status rather than silently replacing the preference. Candidate page size is a keyboard setting, independently applied. [OwlCandidatePanelSettings.swift:OwlCandidatePanelSettings] [OwlSettingsView.swift:persistAndApplyCandidatePageSize]
- App mode memory defaults on but records user changes rather than blindly forcing the initial seed. Ordinary quick-phrase candidates default off. Cloud feature opt-ins and local experiment flags remain distinct preferences. [OwlAppInputMemory.swift:OwlAppInputMemory] [OwlKeyboardPreferences.swift:OwlKeyboardPreferences] [OwlExperimentalPreferences.swift:OwlExperimentalPreferences]
- Template IDs survive edits; a copied entry gets a new identity. Invocation modes are search-only, candidate confirmation, and automatic expansion. Pending imports cannot execute. Candidate marker resolution checks the current library; a displayed title is not an executable identity. [OwlTemplateStore.swift:OwlTemplateEntry] [OwlTemplateStore.swift:resolveCandidate] [OwlRaycastImport.swift:enableAfterReview]
- Saves can require an expected library baseline and publish the commit notification only after storage succeeds. Failed editor saves preserve the draft and previous library. Restore previews carry a baseline and explicit conflict choices; deletion and restore retain full-library backups. [OwlTemplateStore.swift:save] [OwlTemplateBackup.swift:OwlTemplateBackup] [OwlTemplatePage.swift:save]
- Migration preserves source snapshots and recovery state. Raycast import preserves source syntax and leaves unsupported or ambiguous content pending; imported entries default to search-only. Enabling reviewed content or converting it to literal text is explicit. [OwlTemplateMigration.swift:OwlTemplateMigration] [OwlRaycastImport.swift:OwlRaycastImport] [OwlTemplatePage.swift:enableReviewedDraft]
- Template rendering accepts frozen time/calendar/locale/timezone and clipboard context; parsing/rendering failures become diagnostics. Plain text retains braces literally, and legacy double-brace syntax is distinct from standard dynamic fields. Required values and clipboard decisions must resolve before a result is ready. Editor trial values are not persisted. [OwlTemplateEngine.swift:OwlTemplateEngine] [OwlTemplatePage.swift:OwlTemplatePage]
- Legacy quick-send JSON is authoritative; the text table is a derived projection. Legacy loading collapses repeated variant prefixes. Legacy prompts share trigger-code validation with quick sends; they do not define the current unified editor route. [OwlQuickSendPage.swift:OwlQuickSendStore] [OwlPromptStore.swift:OwlPromptStore] [OwlTemplateMigrationView.swift:OwlTemplateSettingsRoute]
- Clipboard history defaults off and captures only through an explicit action, storing at most 20 deduplicated strings truncated to 2,000 characters each. Template clipboard use does not turn on history. Provider secrets use secure fields and the Keychain registry rather than plaintext settings snapshots. [OwlClipboardPage.swift:OwlClipboardStore] [OwlSettingsActions+Stores.swift] [OwlAIPage.swift:OwlAIPage]
- Onboarding practice requires actual Owltype marked-text/commit evidence for the target sentence; pasted text does not pass. The schema-step progress animation completes on a timer after its callback and is not itself deployment evidence. Support-bundle redaction replaces the home directory path; it is not a general content scrubber. [OwlOnboardingPractice.swift:OwlPracticeProof] [OwlOnboardingView.swift:startDeploy] [OwlSettingsPages.swift:redact]
- Native template file dialogs capture their containing visible window, reject overlapping sheets, and revalidate that window before opening a subsequent import/restore preview. The body editor disables substitutions and drops undo history on document replacement. [OwlTemplatePage.swift:presentFilePanel] [OwlTemplatePage.swift:OwlTemplateBodyEditor]

## Side Effects

Persists preferences, template/legacy-library files, private clipboard history, transaction journals and backups; invokes explicitly requested engine activation, resource preparation, provider/model probes, Keychain updates, permission prompts, system input-source selection, and Sparkle checks. UI actions open native panels, folders, font/source URLs, or export user-selected files. Diagnostics launches `/usr/bin/log`, reads its output, and retains a 64 KiB text suffix. Onboarding probes input-source state and schedules UI timers.
