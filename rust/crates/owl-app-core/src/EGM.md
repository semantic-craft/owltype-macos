# Application business core

## Overview

This directory owns application decisions behind the C ABI. Most interfaces accept serializable facts and return values or requested effects. `lib.rs` exports the modules; `storage.rs:Host` supplies primitive effects and `template_session.rs:Session` owns stateful event dispatch. Input-engine composition remains in the separate engine/runtime crates.

## Invariants

- `storage.rs:persist` reads back written JSON bytes. `locked`/`process_locked` delegate lock acquisition and release to the host, so adapters must support nested use and return truthful effects. A returned operation plan does not execute itself.
- `config_writer.rs:authorize` allows exact `MANAGED` names and rejects `user.yaml`, `installation.yaml`, `custom_phrase.txt` and names containing `.userdb`. `write_managed` backs up before replacement and appends a rollback manifest. Its standalone `rollback` is best effort and ignores individual replacement failures; durable template recovery is the stronger path below.
- `template_library.rs:validate` requires format version 1, unique UUIDs, nonblank title/body, valid active triggers and nonconflicting candidate aliases. Candidate codes are lowercase ASCII letter/digit strings up to 32 bytes; automatic triggers begin `;;`. Immediate automatic triggers cannot prefix another trigger (`automatic_index`). Pending imported entries retain source content and cannot execute through `Entry::execution_issue`.
- `template.rs:parse` distinguishes plain text, standard dynamic fields and legacy double braces. Named parameter equality and options use NFC; token ranges/cursor offsets use UTF-16. `render` preserves unresolved field text, reports missing values/temporal facts, requires an explicit empty-clipboard decision and rejects a cursor inside a grapheme or an empty result. Calendar arithmetic/formatting facts come from the host.
- `template_session.rs:Invocation` freezes context once, checks binding monotonically, admits one dispatch, and rejects stale completion generations. Cancellation cannot retract an already dispatched write. The runtime tracks entry and policy revisions; deleted previously known entries cannot match a binding. Recognizer paths are checked against the supplied index.
- `template_transaction.rs:batch` requires distinct managed write targets and writes the activation state last, after library validation/readback. Durable `Journal` recovery validates allowed snapshot/target sets, hashes and phases; it accepts a landed activation only if all expected bytes match. Restoration refuses files changed by someone else. Ordinary `save` uses a rollback batch; `commit_library` and backup/migration flows use the durable journal.
- `template_migration.rs` snapshots original quick-send/prompt files, preserves source bytes and checks them again before commit. Invalid JSON is not replaced with derived candidate tables. `template_backup.rs:decode_backup` rejects unsupported fields/version and duplicate IDs; backup export verifies temporary bytes before rename. Restore compares the expected baseline and rejects trigger conflicts. Raycast import preserves original metadata and leaves incompatible syntax pending (`template_import.rs:compatibility`).
- `host_delivery.rs:Delivery` reserves a result slot once, consumes effect admission and callback tokens, checks source/revision/text/ranges, and distinguishes attempted writes from confirmed text and cursor placement. Cursor targets must be grapheme boundaries in UTF-16. `Focus` consumes each poll token, preventing duplicate dispatch. Native facts are evidence inputs, not independently measured here.
- `agent.rs` exposes only opted-in, reviewed, executable templates. Agent rendering always supplies an empty clipboard and adds a warning for clipboard fields. Delivery validation allows request IDs of 1–128 ASCII letters/digits/`.-_:`, nonempty text up to 20,000 Unicode scalars, and 5,000–600,000 ms timeouts (default 120,000). Callers must validate before `DeliveryCoordinatorCore::handle_event`; the state machine itself handles one pending request, attaches same-ID waiters and caches outcomes for 600 seconds with a default 256-entry limit. Writing begins only after a confirmed user-decision event and target checks; host outcomes retain verified/unverified distinction.
- `ai_business.rs:Conversation` and `ai_selection.rs:Rewrite` reject stale generations; conversation history keeps at most 10 completed turns. Failover is allowed only before content has yielded and for invalid endpoints or HTTP 401/402/403/404. Selection context is explicitly supplied and clipped by grapheme count. Formatting accepts model reflow only when the normalized alphanumeric fingerprint matches (`ai_selection.rs:rule`).
- `provider_store.rs` keeps secret material in native effects, using references and digest facts. Endpoint-origin changes with an empty replacement key are rejected. Secret writes are staged before profile mutation; failure rereads determine whether new profile references landed before cleanup. High-level `upsert`/`replace` require HTTPS; lower-level raw mutation dispatch is a separate surface. `provider_wire.rs:Stream` buffers split UTF-8 bytes until lines, accepts `data:` events, and treats explicit terminal events/`[DONE]` as completion.
- `ai_verification.rs:Receipt` consumes per-anchor generations; cancellation/manual fallback invalidates older results. A source response produces `success` before separate user confirmation. The current receipt copy labels missing law results as suspected fabrication while retaining pending status; it is not proof that a law does not exist. `safeURL` validates HTTP(S) and rejects credentials; provider source collectors have looser URL-prefix checks and should not be treated as this validator.
- `resource_contract.rs:validate` checks manifest version, path/digest/license/capability fields and calculated SHA-256. Generation verification compares decoded persisted manifest fields, payload sizes/hashes, optional complete marker and trusted SQLite tables/columns plus integrity checks. Relative payload paths reject empty/dot/parent components and symlinks along the checked path. Root configuration requires absolute, canonical, nonoverlapping directories and an existing user root.
- `resource.rs:Store` locks by input kind, verifies staged files before publishing, writes `.complete`, makes files read-only, and keeps preparation separate from active-pointer replacement. Activation checks its previous-generation identity again; an existing identical digest is reverified. Rollback verifies the previous record. Leases copy a validated generation into a per-lease runtime directory; release matches stored identity and recovery removes only leases whose host-reported process is dead. Active-generation lookup may fall back to a validated previous record (`resource_catalog.rs:dispatch`).
- `user_migration.rs` reads only `sync/<installation>/*.userdb.txt`, rejects nonregular/symlink paths and files over 64 MiB, limits each line to 64 KiB and each snapshot to 500,000 entries. It maps supported Pinyin/Wubi schemas, coalesces duplicate records by maximum commits, clamps positive weights and preserves negative commits as deletions. Decay/tick and user-created-word semantics are not imported. Stage identity/digests and exact files are rechecked; engine reports must match request ID and source/issue/record/pin counts. The engine remains journal owner.
- `client_capability.rs` denies nonzero-character-index attributes before overrides; other capability checks evaluate explicit denied/allowed overrides before their remaining host/privacy rules. `foundation_text.rs` mirrors Foundation trimming/newline behavior, and `lib.rs:utf16_range` rejects split surrogate boundaries.

## Side Effects

- `storage.rs:Host` effects cover file reads/writes/removals, process/cross-process locks, timestamps/UUIDs, collation, backup/rename/checkpoints and commit notifications. Provider effects additionally access native secret references, verification metadata and profile/workspace storage. Native adapters own networking, Keychain values, GUI/accessibility and actual text insertion.
- `resource_contract.rs:configuration` creates non-user roots; its digest/generation checks read files and SQLite. `resource_catalog.rs:build` copies bundled inputs into a candidate tree with create-new destinations, writes compatibility/manifest files and counts SQLite rows. These functions perform real filesystem I/O directly.
- `resource.rs` requests staging, copies/download transport, chmod/sync/rename, active/journal writes, progress callbacks and runtime lease cleanup through `resource_native_*` effects. `user_data.rs:reset` backs up selected database/dictionary items before removal and reports restoration failures explicitly.
- Pure rules, parser/renderer, protocol formatting and event state transitions mutate only supplied or owned memory. They do not independently prove native effects occurred.

## Verification

From `rust/`, use `cargo test -p owl-app-core`; exercise native effect adapters and C ABI for storage interruption/recovery, split UTF-8/UTF-16, stale callbacks, clipboard decisions and actual host delivery. Bootstrap read all production Rust in this directory and `pure_rules`; the trailing `agent.rs` unit-test module was excluded. Compiled JSON catalogs were inspected up to 200 lines per file under the bootstrap configuration-read rule; no provider availability, filesystem transaction or native acceptance was executed.
