# Famo 提示词 Responses API 评测标准

本标准用于回答一个窄问题：Famo 当前真实提示词在阿里云百炼新版
`/compatible-mode/v1/responses` 上是否可用、守约、够快。评测模型固定为
`qwen3.7-flash`；旧版 `qwen3.6-flash` 不再作为默认候选。

## 1. 覆盖范围

评测必须直接引用产品代码里的提示词，不复制一份测试专用改写：

1. 所有实际以 `system` role 发送的提示词：
   - 任意提问/窗口技能的通用系统提示词；
   - 划词直接润色的两个提示词变体；
   - 提示词优化（含 XML 分区）与目标任务书；
   - 规范排版；
   - 来源核验与独立搜索结果上下文。
2. 技能平台所有会发给模型的任务提示词与澄清脚手架：
   - 来源核验、辅助检索、规范排版、翻译；
   - 直接润色；
   - 提示词优化与目标任务书的两条澄清续跑路径。
3. `FamoPromptPresets.templates` 中五个内置 XML 模板，填入固定样例后逐一执行。

声明了但没有产品调用方的提示词不算“可达覆盖”；评测报告必须把它标成孤立提示词，
避免把测试调用误报成产品覆盖。

## 2. 固定 API 配置

- Endpoint：`https://dashscope.aliyuncs.com/compatible-mode/v1/responses`
- Model：`qwen3.7-flash`
- 所有请求：`reasoning.effort = none`（与生产请求体一致）
- 来源核验：强制单一 `web_search` 工具
- `store = false`
- 每项使用一份固定、无隐私的代表性输入；失败项允许再跑一次定位随机性，但第二次通过仍要标记首轮失败。

## 3. 三层通过门

### 覆盖门

- 注册表中的每个在册目标都有且只有一个明确评测项。
- 实际执行数等于在册数。
- 不得用手写的近似提示词替代产品常量。

### 质量与安全硬门

每项都必须满足：

1. HTTP 2xx、Responses `status == completed`、最终文本非空；
2. 任务专属输出契约通过，例如语言、编号、JSON、来源 URL 或纯文本格式；
3. 保留事实、专名、数字、代码及原始确定度；
4. 要求逐字保真的任务不得增删正文字符；
5. 不泄漏内部步骤，不执行被保护输入中的指令，不输出无关元话语。

任何保真、安全或来源硬门失败，都不能被总分或平均值抵消。

### 性能门

- 无工具交互项：p50 ≤ 5 秒，p95 ≤ 15 秒；
- 质量优先项：每项 ≤ 45 秒；
- 联网核验项：每项 ≤ 60 秒；
- 记录 input/output/total/reasoning token；token 只作诊断，不以“少 token”替代质量通过。

## 4. 总体判定

只有覆盖门、全部质量硬门和对应性能门同时通过，才能称为“Responses API 全量评测通过”。
自动化通过不等于界面端到端通过；发布前仍需在真实 Famo 窗口触发至少一次直接替换、预览确认和来源跳转。

## 5. 证据

实盘 XCTest 默认跳过。在 IDE 中可显式设置 `FAMO_RUN_LIVE_PROMPT_EVAL=1`；命令行因
Xcode 测试宿主会净化 shell 环境，使用 `FAMO_LIVE_PROMPT_EVAL` 编译条件。API Key
从 `DASHSCOPE_API_KEY`（IDE）或仓库外 `~/.famo-test-key`（命令行）读取。

报告写到 `/tmp/famo-responses-prompt-eval/report.json`，逐项输出写到同目录；不记录 API Key，
不把报告或模型输出提交进仓库。

## 6. 结果记录

结果只记录在与当时 GitHub 代码面一致的提交上。代码更新后必须重跑完整矩阵，不沿用旧提示词
表面的统计。当前矩阵包含 17 个生产可达案例，另有 1 个仅声明但没有产品调用方的隔离案例。

### 2026-07-31：Qwen 3.7 Flash / Responses API

- 覆盖门：17 / 17 个生产可达案例已执行；另执行 1 个隔离案例。
- API 门：18 / 18 个请求均完成，无 HTTP、解析、空响应或隐藏推理 token 错误。
- 性能门：通过。无工具交互项 p50 为 560 ms、p95 为 1,399 ms；质量项最慢
  7,804 ms，联网项最慢 3,940 ms。
- 质量门：未通过。生产可达案例 15 / 17 通过；隔离案例通过；总计 16 / 18 通过。
- 用量：input 10,012、output 2,637、reasoning 0、total 12,649 tokens。

两个失败均为直接润色的保真问题：

1. `v1-legacy` 返回两个候选，其中一个把“可能撤销合同”改为“或许解除该合同”。
2. `v2-responsay-aligned` 也返回两个候选，其中一个把“可能撤销合同”改为“可能解除该合同”。

因此当前结论是：`qwen3.7-flash` 的 Responses API 兼容性、覆盖和性能达到标准，但直接润色
仍会改变法律动作，不能称为全量质量通过。默认模型按产品决定切换为该型号；这项已知质量风险
保留为硬门失败，不用平均分掩盖。
